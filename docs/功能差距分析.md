# 功能差距分析（对标同类产品）

> 结论先行：当前版本已经把「桌面月历 + 待办 + 提醒 + 托盘 + 搜索 + WebDAV 同步 + AI 对话」的骨架做完了，
> 但和同类产品比，最缺的不是花哨功能，而是两类「地基」：
> **① 日程的时间维度（重复、精确到时刻的提醒、周视图/时间轴、拖拽改期）；② 数据能带走、能在手机上用（导出、Web/PWA）。**
> 其余的桌面组件、天气、纪念日、习惯打卡、统计等，是「像不像一个成熟桌面日历」的加分项，按定位取舍。

## 2. 我们现在的家底（对照源码）

已完成且做得不错：

- 月历：农历、节气、节日、休班标记；年月跳转、「今」；节日/节假日来自 `lunar-typescript` + 本地修正表
- 任务：日期、项目分类、优先级、颜色、备注 Markdown；删除可撤销
- 提醒：提前 1–5 天，到点系统通知，点通知打开对应日程
- 常驻：托盘/菜单栏、关闭不退出、托盘里勾任务；开机/登录自启；单实例
- 视图：月视图 + 待办（迷你日历 + 当天日程）+ AI 对话
- 搜索：标题/备注（`Ctrl+K` / `⌘K`）
- 同步：WebDAV（坚果云/群晖/Nextcloud），自动同步 + 冲突合并；本地每日备份
- AI：DeepSeek 等 OpenAI 兼容接口，对话式分析任务
- 深色模式、窗口位置记忆、原子写、损坏自动备份

## 4. P0：不做就不像成熟产品

### 4.1 重复任务/日程（最高优先）
- 现状：`src/renderer/src/domain/types.ts` 里已经有 `Repeat = 'none' | 'daily' | 'weekly' | 'monthly' | 'yearly'`，
  但 `expandTasks()` 只按单日落位，`TaskDrawer` 也没有重复入口——等于只留了字段没实现。
- 要做：重复规则（每周几 / 每月几号 / 每年，农历生日年份要特殊处理）、例外（跳过/改期一次）、
  「仅此条 / 之后全部」编辑、重复实例的提醒与完成状态（打卡式 vs 每个实例独立）。
- 竞品：TickTick、Things、Fantastical、时光序 都是标配；这是「日程管理」和「一次性待办」的分水岭。

### 4.2 时间维度：精确时间提醒 + 周视图 + 拖拽
- 现状：`Task.time` / `endTime` 字段存在但界面没有时间输入；`remindAtFor()` 固定
  「截止日 09:00 往前推 N 天」，不能设「提前 15 分钟」「任意时刻提醒」；没有周视图/时间轴，不能拖拽改期。
- 要做：
  - 任务时间（HH:mm，可选结束时间、跨天）
  - 提醒：自定义时刻、提前 5/15/30 分钟/1 小时/1 天、**稍后提醒（5/10 分钟）**
  - 通知按钮：完成 / 稍后（macOS 通知 action 支持有限，可用点击后弹小窗）
  - 周视图 + 时间轴 + 拖拽改期
- 竞品：指尖时光、优效、时光序、TickTick 全都有；这是桌面日历最核心的「手感」。

### 4.3 快速记录（自然语言 + 全局快捷键）
- 现状：只能打开抽屉手填；没有全局快捷键，也没有自然语言解析。
- 要做：`Alt+Space`（Win）/ `⌥Space`（mac）唤起快速输入框，输入「明天下午 3 点和老王开会 #工作 !高」
  直接生成任务；解析优先本地规则，复杂语句走已配置的 DeepSeek（正好把现有 AI 能力用起来）。
- 差异化价值：这是「AI 计划清单」最容易感知的卖点，也比纯对话分析更实用。

### 4.4 数据可带走：导出 + 手动备份入口
- 现状：只有「导入数据」（`SettingsDialog.tsx` 205 行）；`store:backup` IPC 有，但没有界面按钮；
  每日自动备份在数据目录 `backups/`，用户看不到也导不出。
- 要做：导出 JSON / Markdown / ICS（Excel 可选）；「立即备份」按钮 + 打开备份目录；
  导入导出双向。对「本地优先」产品，导出能力就是用户信任的底线。

### 4.5 任务组织：子任务 + 标签
- 现状：项目只有一级，任务不能拆子项，也没有标签。
- 要做：任务 checklist（子项可勾选）、标签（多标签、颜色、搜索/筛选）。
- 竞品：Things 的 checklist、TickTick 的清单/子任务都是高频功能。

### 4.6 多端：至少 Web/PWA
- 现状：只有 Windows/macOS 桌面端。坚果云同步只能服务「多台电脑」，通勤/外出场景接不上。
- 建议：先做只读 + 快速添加的 Web/PWA（同一份 data.json 走 WebDAV），成本远低于原生 App；
  真要原生 App 再评估 Flutter/RN 或 Tauri 移动端。

## 5. P1：决定竞争力的加分项

1. **桌面常驻形态**（优效/指尖时光的卖点）：置顶半透明「桌面月历挂件」、今日待办浮窗、
   Windows 任务栏时钟、macOS 菜单栏点击弹今日待办面板（现在菜单栏只有菜单，没有面板）。
2. **日历互操作**：ICS 导出/订阅（单向）、系统日历集成（macOS EventKit / Windows 日历）、
   CalDAV/Google/Outlook 账号（只读同步即可，避免做双写合并）。
3. **生活向功能**（中国桌面日历用户预期）：天气（指尖时光核心卖点）、纪念日/生日/倒数日
   （与「重复任务」共用一套引擎）、习惯打卡、番茄专注。
4. **统计 + AI 周报**：完成率、项目/优先级分布、月/周报表；AI 自动生成「本周复盘」，
   这是现有 AI 能力最容易做出差异化的方向。
5. **发布工程**：`electron-updater` + GitHub Releases 自动更新（Release 已经有了，接一下即可）、
   Windows/macOS 签名与公证、崩溃日志上报、日志导出。
6. **体验细节**：主题/字体大小/背景自定义、快捷键体系（Space 勾选、⌘N、⌘F、↑↓ 选日期）、
   全键盘导航、无障碍、英文界面。

## 6. P2 / 建议谨慎做

- **共享清单/团队协作**：需要账号体系和服务器，与「本地优先 + 用户自己的坚果云」定位冲突，
  除非要做团队版，否则不建议。
- **记账/日记/生理期/健康**（时光序式堆叠）：会稀释「计划清单」定位，用户认知会乱。
- **原生手机 App**：成本最高、迭代最慢，先用 Web/PWA 验证需求。
- **强制账号/自建云**：现在的「无账号、数据在你自己的坚果云」是隐私优势，别丢。

## 7. 定位建议与路线

**一句话定位**：自带 AI 的桌面计划清单——本地优先、数据在你自己的坚果云，Windows/macOS 原生体验。

**差异化三角**：
1. **桌面原生**：托盘/菜单栏/桌面挂件/全局快捷键，比网页版日历更「随手」；
2. **AI**：自然语言建任务、AI 周报、排期建议；用用户自己的 API Key，隐私友好；
3. **数据自主**：WebDAV/坚果云、开放格式导出、无强制账号——和「云账号全家桶」形成对比。

**建议路线**（按投入产出排序，工作量为粗估）：

| 版本 | 内容 | 估算 |
|---|---|---|
| v0.13 | 重复任务 + 任务时间 + 精确/稍后提醒 + 导出(JSON/MD/ICS) + 手动备份入口 | 8–12 人日 |
| v0.14 | 周视图/时间轴 + 拖拽改期 + 全局快捷键快速添加（AI 解析）+ 子任务/标签 | 10–15 人日 |
| v0.15 | 桌面挂件/菜单栏面板 + 天气 + 纪念日/倒数日（复用重复引擎） | 10–15 人日 |
| v1.0 | Web/PWA 多端 + 统计/AI 周报 + 自动更新 + 签名公证 | 20+ 人日 |

> 注：以上只是功能面的差距分析；如果只做「自用 + 小圈子分发」，P0 里优先做重复任务、提醒增强、导出即可，
> 桌面挂件和天气属于「桌面日历」品类的仪式感，可以按时间安排。
