## 0. 结论先行

| 项 | 结论 |
|---|---|
| 产品定位 | 本地优先的「月历 + 日程待办 + 项目分类」桌面应用，Windows / macOS 同一套代码，中文界面，离线可用，可选 WebDAV 同步 |
| 技术路线 | **Electron + React 18 + TypeScript + Vite + Tailwind**，数据用**单文件 JSON**（原子写 + 每日备份），不引入数据库和账号体系 |
| 首版范围 | 截图里的**月视图**和**日详情 + 项目**两屏做全，另补「新增/编辑任务」「提醒」「WebDAV 同步」这三个截图外但必需的闭环；待办清单、番茄钟、笔记、标签先留图标占位 |
| 工期 | M1–M5 约 **13–19 个工作日**（核心功能 10–14 天，WebDAV 同步 +3–5 天） |
| 同步 | 单文件 JSON 放坚果云 WebDAV，**按记录合并**（`updatedAt` + 修订号，删除用墓碑），不做整文件覆盖 |
| 硬约束 | **macOS 的 .dmg/.app 无法在 Windows 上产出**，需要一台 Mac 或 GitHub Actions 的 macOS runner；Windows 端我可以直接出 NSIS 安装包 + 免安装版 |

一句话：**用 Web 技术做界面、Electron 做壳、JSON 做存储**，是这套需求在「两平台都能跑 + 我能独立交付 + 不折腾原生编译」三者之间最稳的解法。

## 2. 需求清单

### 2.1 核心用户故事

- 作为用户，我打开软件就能看到本月每天有哪些事，一眼区分工作日/休息日。
- 我能在一分钟内把一件事记到某一天，并归到某个项目。
- 我能勾掉已完成的事，且历史记录仍可回看。
- 我能只看"工作"或"科研"，把生活和工作的安排分开。
- 到点我能收到系统通知，不错过事情。

### 2.2 P0（首个可用版本，必须）

| 编号 | 需求 | 验收标准 |
|---|---|---|

| F-02 | 农历/节气/节日 | 每格显示农历日或节日/节气；覆盖 1900–2100（库能力范围） |

| F-05 | 任务增删改 | 弹窗编辑标题/日期/项目/备注；删除有确认与撤销 |
| F-06 | 完成勾选 | 月视图与日详情均可勾选，状态实时同步 |

| F-11 | 今日定位 | 「今天」按钮回到当月并选中今天 |

## 3. 技术选型

### 3.1 候选对比

| 方案 | 包体积 | 内存 | 开发速度 | 双平台一致性 | 本机可行性 | 结论 |
|---|---|---|---|---|---|---|
| **Electron + React** | ~120MB 安装包 | ~200MB | ★★★★★ | ★★★★★ | 已有 Node 24，零额外环境 | **推荐** |
| Tauri 2 + React | ~8MB | ~80MB | ★★★☆ | ★★★★ | 需装 Rust + MSVC 工具链（约 2–4GB） | 备选 |
| Flutter Desktop | ~30MB | ~120MB | ★★★ | ★★★★ | 需装 Flutter SDK；中文日历生态弱 | 不选 |
| Avalonia (.NET) | ~40MB | ~150MB | ★★★ | ★★★★ | 需 .NET SDK，UI 细节还原成本高 | 不选 |
| Qt / C++ | ~30MB | ~80MB | ★★ | ★★★★ | 环境复杂，迭代慢 | 不选 |
| PWA / 纯网页 | 0 | — | ★★★★★ | ★★★★★ | 无系统通知可靠性、无托盘、不像桌面软件 | 不选 |

### 3.2 为什么是 Electron（而不是更"先进"的 Tauri）

1. **本机零环境成本**：当前只有 Node 24，没有 Rust；Tauri 首次构建要装 Rust + Visual Studio Build Tools，光环境就半天。
2. **UI 还原度**：截图是典型的 Web 风格（圆角、浅色块、细字重），Tailwind 能 1:1 还原；Tauri 也是 WebView，但 Windows 上 WebView2 版本差异会带来渲染细节偏差。
3. **生态成熟**：通知、托盘、单实例、自动更新、打包签名都有现成方案，踩坑少。
4. **代价可接受**：安装包 120MB、内存 200MB，对一个每天开着的桌面日程工具不算问题。真要极致轻量，v1.0 之后可以评估迁移 Tauri，业务代码（React + 数据层）可复用 90%。

> 如果你更在意体积/内存，或者本机愿意装 Rust，我们可以改 Tauri，但工期预计 +50%，且 Windows 首次构建时间会明显变长。

### 3.3 技术栈明细

| 层 | 选型 | 说明 |
|---|---|---|
| 壳 | Electron 33+ | 主进程负责窗口、托盘、通知、文件 IO |
| 构建 | electron-vite + electron-builder | 开发热更新、三平台打包 |
| UI | React 18 + TypeScript | 严格模式，组件全部带类型 |
| 样式 | Tailwind CSS v4 + CSS 变量 | 设计 token 集中管理，便于做深色模式 |
| 组件 | Radix UI（Dialog/Popover/Dropdown/Toast）+ lucide-react 图标 | 只取无样式原语，外观自己写 |
| 状态 | Zustand | 轻量，无样板代码；按 `projects / tasks / ui` 分 store |
| 日期 | date-fns | 纯函数、tree-shaking 友好 |
| 农历 | lunar-typescript（6tail，MIT） | 农历、节气、节日、`HolidayUtil` 调休数据 |
| 校验 | zod | 导入/持久化/远端数据校验 |
| 同步 | webdav（npm）+ Electron `safeStorage` | 坚果云 / 群晖 / NextCloud 通用 WebDAV |
| 测试 | Vitest + Playwright(Electron) | 日期/农历/统计逻辑单测；关键流程 E2E |

### 3.4 存储方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 单文件 JSON | 零原生依赖、易备份/导入、可直接看 | 无并发、全量写 | **首版采用**（个人数据量 < 1 万条足够） |
| better-sqlite3 | 查询强、事务 | 原生模块需按 Electron ABI 重编译，双平台易翻车 | 数据量上来再换 |
| IndexedDB | 浏览器原生 | 数据藏在 Chromium profile 里，用户无法备份 | 不选 |

**JSON 存储的具体做法**：内存持有全量 `AppData` → 变更后 300ms 防抖 → 写 `data.json.tmp` → `fsync` → 原子 rename 覆盖 → 每次启动把上一版复制到 `backups/data-YYYYMMDD.json`，保留最近 14 份。彻底避免"写一半断电导致文件损坏"。

### 3.5 同步方案对比

| 方案 | 冲突处理 | 复杂度 | 结论 |
|---|---|---|---|
| 整文件覆盖 + 修改时间判断 | 后写覆盖先写，**会丢数据** | 低 | 不选 |
| 每条记录一个文件 | 天然隔离，但请求多、目录乱 | 中 | 不选 |
| **单文件 + 按记录合并** | 按 `updatedAt`/`rev` 取新，删除用墓碑 | 中 | **采用** |
| 自建服务端 / Supabase | 最强，但要服务器与账号 | 高 | 超出范围 |

坚果云 WebDAV 的请求频率限制较严（每分钟约 30 次），因此策略是"**变更后延迟 5 秒合并上传一次**"，而不是每条任务一次请求。

## 4. 架构设计

### 4.1 进程模型

```
┌──────────────────────────── Main（Node） ────────────────────────────┐
│ 窗口/托盘/单实例   │  文件存储 + 原子写 + 备份  │  提醒调度器  │ 更新  │
└───────────▲──────────────────────▲──────────────────────▲───────────┘
            │ contextBridge (preload, 白名单 IPC)
┌───────────┴──────────────────────┴──────────────────────┴───────────┐
│ Renderer（React）                                                    │
│  Zustand Store ── 视图层（月视图 / 日详情 / 弹窗 / 设置）             │
│  domain/：日历网格、农历、任务展开、重复规则、统计（纯函数，可单测）    │
└─────────────────────────────────────────────────────────────────────┘
```

**原则**：渲染进程不碰文件系统；主进程不碰业务规则。所有业务计算是纯函数，方便单测和将来换壳。

### 4.2 IPC 接口（刻意保持很小）

| 通道 | 方向 | 用途 |
|---|---|---|
| `store:read` | R→M | 读取全量数据（启动时一次） |
| `store:write` | R→M | 提交全量数据（防抖 + 原子写），返回 `{ok, revision}` |
| `store:backupNow` | R→M | 手动备份 |
| `store:export` / `store:import` | R→M | JSON 导出/导入（系统文件对话框） |
| `notify:sync` | R→M | 提交未来 7 天提醒列表，主进程重建定时器 |
| `notify:test` | R→M | 测试通知 |
| `win:minimize` / `win:toggleMaximize` / `win:close` | R→M | 自绘标题栏按钮 |
| `win:setAlwaysOnTop` | R→M | 可选 |
| `app:info` | R→M | 版本号、数据目录、平台 |
| `app:openDataDir` | R→M | 打开数据文件夹 |
| `sync:setCredential` | R→M | 保存并测试 WebDAV 账号（加密后落盘） |
| `sync:now` | R→M | 手动立即同步 |
| `sync:status` | M→R | 推送同步中 / 成功 / 失败 / 离线状态与时间 |
| `deep:changed` | M→R | 数据被外部改动（导入后）通知刷新 |

### 4.3 数据模型

```ts
type ID = string;                       // nanoid(10)
type DateStr = string;                  // 'YYYY-MM-DD'
type TimeStr = string;                  // 'HH:mm'

interface Project {
  id: ID;
  name: string;
  color: string;                        // '#3E8EF7'
  icon: string;                         // lucide 图标名，如 'briefcase'
  sort: number;
  archived: boolean;
  updatedAt: string;                    // 同步用
  rev: number;                          // 本地修订号，单调 +1
  deletedAt?: string;                   // 墓碑；有值即视为已删除
}

interface RepeatRule {
  freq: 'daily' | 'weekly' | 'monthly' | 'yearly';
  interval: number;                     // 每 N 天/周/月/年
  weekdays?: number[];                  // 0=周日 … 6=周六（weekly 用）
  until?: DateStr;
}

interface Task {
  id: ID;
  projectId: ID;
  title: string;                        // 1–200 字
  notes?: string;
  startDate: DateStr;
  endDate?: DateStr;                    // 跨天任务（P1 才渲染成条）
  startTime?: TimeStr;                  // 省略 = 全天
  endTime?: TimeStr;
  done: boolean;
  doneAt?: string;                      // ISO
  color?: string;                       // 单条覆盖项目色
  priority?: 0 | 1 | 2;
  repeat?: RepeatRule;
  remindAt?: string;                    // ISO，含时区偏移
  sort: number;                         // 同日排序
  createdAt: string;
  updatedAt: string;                    // 同步用
  rev: number;                          // 本地修订号，单调 +1
  deletedAt?: string;                   // 墓碑；有值即视为已删除
}

interface Settings {
  weekStart: 1 | 0 | 6;                 // 周一 / 周日 / 周六
  showLunar: boolean;
  showHoliday: boolean;
  theme: 'light' | 'dark' | 'system';
  closeToTray: boolean;
  launchAtLogin: boolean;
  defaultProjectId: ID | null;
  lastView: 'month' | 'day';
  window: { x?: number; y?: number; w: number; h: number; maximized: boolean };
}

interface AppData {
  schemaVersion: 1;
  projects: Project[];
  tasks: Task[];
  settings: Settings;
  meta: { createdAt: string; lastBackupAt?: string; deviceId: string };
}
```

重复任务在存储层**只存规则**，渲染时按需展开到某一天（`getTasksForDate`），避免生成无穷多条记录。


### 4.5 关键算法

**月历网格**：以"该月 1 号是周几"反推第一格日期，向前补齐到周起始；行数 = `ceil((前置空格 + 当月天数) / 7)`，所以 2026-10 正好 5 行，和截图一致（9/28–11/1）。

**农历/节日优先级**：法定节日（含调休名） > 传统节日（春节/中秋…） > 节气 > 农历日（初一显示"X月"）。`lunar-typescript` 的 `HolidayUtil.getHoliday(y,m,d)` 提供 `work/rest` 标记；**内置表可能晚于官方发布**，因此：

1. 代码内置 `holidays/*.json`（按年维护，含 2026 全年）；
2. 设置页提供"节假日数据版本"与手动覆盖（把某天标为休/班）；
3. 启动时若当前年份无数据，退化为"仅周末高亮"，不阻塞使用。

**任务条溢出**：单元格高度动态测量，能放几条画几条，其余 `+N`；`+N` 悬浮显示当日全部任务的小浮层。

**提醒调度**：主进程持有按时间排序的最小堆 → 每 20s tick 一次（避免长定时器在睡眠后失准）→ 命中则 `new Notification()`；同时监听 `powerMonitor` 的 `resume`/`unlock-screen` 立即重算。通知按钮：`完成` / `5 分钟后`。

### 4.7 同步设计（WebDAV）

**目标**：两台机器都离线可用，联网后自动收敛到同一份数据，且任何一台的修改都不丢。

**远程文件**：`<WebDAV 根>/指尖时光/data.json`，格式与本地一致（不含 `settings.window` 等本机偏好）。

**合并规则**（`merge(local, remote)`，双向对称）：

1. 以 `id` 为键求并集；
2. 同一条记录，比较 `(updatedAt, rev, deviceId)` 三元组，取较大者；
3. 任一侧存在 `deletedAt` 且该墓碑比另一侧的编辑更新，则删除生效；否则视为"删除后又编辑"，保留编辑；
4. 墓碑保留 90 天后由任意一台机器在合并时清理（防止另一端离线太久把已删任务带回来）；
5. `settings` 中只同步"周起始/显示农历/默认项目"这类跨机偏好，窗口尺寸、开机自启、托盘行为留在本机。

**流程**：

```
启动/定时/窗口聚焦
   └─ GET data.json（带 If-None-Match，204/304 直接结束）
        ├─ 无变更 → 结束
        └─ 有变更 → merge(local, remote)
                     ├─ 合并结果 == remote → 仅更新本地
                     └─ 合并结果 != remote → PUT（带 If-Match: 旧 ETag，失败则重试一轮）
本地修改 → 5s 防抖 → 同样先 GET 再合并上传（避免覆盖另一台的并发写入）
```

**凭据**：`safeStorage.encryptString()` 加密后存到 `secrets.bin`；设置页只显示"已配置"与"重新输入"，不回显密码。

**坚果云接入参数**：服务器 `https://dav.jianguoyun.com/dav/`，账号=邮箱，密码=**应用密码**（在坚果云「安全选项 → 添加应用」生成，不是登录密码）。这些由你在设置页填，我不需要拿到。

**降级**：未配置或连接失败时，应用完全按本地模式运行，只在状态栏提示"未同步"，不阻塞任何操作；冲突不弹模态框，合并结果写进日志，可在设置页查看"最近一次同步"详情。
