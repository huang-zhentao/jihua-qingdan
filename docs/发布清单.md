# 发布清单（GitHub Release）

> 目的：把「每次发布要上传什么、怎么上传、怎么校验」固定下来，避免漏传或再次出现中文乱码。

## 1. 硬性要求

- **macOS 版本必须和 Windows 版本一起发布**：GitHub Release 里要同时挂上两个平台的安装包，不能只发 Windows。
  - Windows：`计划清单-<version>-setup.exe`（NSIS 安装包，`npm run dist:nsis`）；可选 `计划清单-<version>-portable.exe`（`npm run dist`）
  - macOS：`计划清单-<version>-<arch>.dmg`（`npm run dist:mac`，Apple Silicon 出 arm64）
- **Release 标题 / 说明必须是正确的 UTF-8 中文**：
  - 历史问题：在 Windows 控制台（GBK 代码页）里直接写中文 notes/描述，会把中文存成 `?`（v0.12.8 的 About 和 Release 都踩过）。
  - 正确做法：中文说明先写成 UTF-8 文件（`.md`），再用 `--notes-file` 提交；设置描述用 `gh repo edit --description`，不要经过 cmd/PowerShell 5 的管道。
- **说明里写清安装方式**：
  - Windows 未签名：SmartScreen →「更多信息」→「仍要运行」
  - macOS 未签名：首次右键 →「打开」，或 `xattr -dr com.apple.quarantine /Applications/计划清单.app`
  - 数据目录：Windows `%APPDATA%\jihua-qingdan`；macOS `~/Library/Application Support/jihua-qingdan`
- **上传前自检**：
  1. `npx tsc --noEmit`、`npm run build` 通过
  2. macOS：`npm run test:mac`（菜单/菜单栏图标/⌘K/通知/关闭隐藏/二次实例）
  3. macOS：dmg 挂载 → 拖入 /Applications → 双击能启动；`codesign --verify` 无报错
  4. Windows：安装包能安装、启动（在 Windows 机器上）
  5. 记录产物 `shasum -a 256`（可选，写在 Release 说明里）

## 2. 发布步骤

```bash
# 1) 构建（各自平台）
npm run dist:nsis            # Windows：安装包
npm run dist                 # Windows：便携版（可选）
npm run dist:mac             # macOS：dmg（在 Mac 上执行）

# 2) 写 UTF-8 说明文件
$EDITOR docs/release-notes-<version>.md

# 3) 创建/更新 Release（注意走代理）
export https_proxy=http://127.0.0.1:7890 http_proxy=http://127.0.0.1:7890
gh release create v<version> --title "计划清单 v<version>" --notes-file docs/release-notes-<version>.md
gh release upload v<version> \
  "dist/计划清单-<version>-setup.exe" \
  "dist/计划清单-<version>-<arch>.dmg" \
  --clobber

# 4) 校验附件齐全
gh release view v<version> --json name,assets --jq '{name, assets: [.assets[].name]}'
```

> 上传需要 GitHub 凭据：本机已用 `gh auth login`（网页设备码）登录 `huang-zhentao`，
> 并执行 `gh auth setup-git` 把凭据存进钥匙串；访问 GitHub 仍需 `proxy-on`。
> 注意：`gh` 安装在 `~/.local/bin/gh`（brew 镜像没有 macOS 27 的 bottle）。
